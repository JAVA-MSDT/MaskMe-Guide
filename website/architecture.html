Core Components

1. @MaskMe Annotation

@Target({ElementType.FIELD, ElementType.RECORD_COMPONENT})
@Retention(RetentionPolicy.RUNTIME)
public @interface MaskMe {
    String DEFAULT_MASK_VALUE = "****";
    Class<? extends MaskCondition>[] conditions();
    String maskValue() default DEFAULT_MASK_VALUE;
}
  • Supports fields and record components
  • Runtime retention for reflection-based processing
  • Multiple condition support through an array
  • Default mask value fallback

2. MaskMeCondition Interface

public interface MaskMeCondition {
    boolean shouldMask(Object maskedFieldValue, Object objectContainingMaskedField);
    default void setInput(Object input) { }
}
  • shouldMask() — Core logic to determine if masking should occur
  • setInput() — Optional method to receive runtime input
  • Access to both field value and containing object for context-aware decisions

3. MaskMeProcessor

The main processing engine. Handles reflection-based field discovery, condition evaluation, type conversion coordination, ThreadLocal management, and nested object processing.

4. MaskMeInitializer

Simplified static facade for common masking operations. Provides automatic ThreadLocal cleanup, varargs support for condition-input pairs, and thread-safe operation.

Framework Integration Architecture

Framework Provider Pattern

public interface MaskMeFrameworkProvider {
    <T> T getInstance(Class<T> type);
}

Abstracts framework-specific bean resolution. Spring uses ApplicationContext.getBean(), CDI uses BeanManager, and pure Java uses manual instance creation.

Design Philosophy: Framework-Agnostic

Why MaskMe doesn't cache condition instances MaskMe delegates lifecycle management to your framework. Without registration, it falls back to reflection (new instance each time). With registration, your framework provides singletons.

❌ Without Registration

@MaskMe(conditions = {AlwaysMaskMeCondition.class})
String field1; // New instance #1
String field2; // New instance #2
String field3; // New instance #3
// 3 separate instances via reflection

✅ With Registration

@Bean
public AlwaysMaskMeCondition always() {
    return new AlwaysMaskMeCondition();
}
// 1 singleton reused 3 times

Field Processing Architecture

Masking Pipeline

Input Object ↓ Field Discovery (Record components or declared fields) ↓ For Each @MaskMe Field: ↓ Condition Evaluation ↓ Should Mask? ──(No)──▶ Skip ↓ (Yes) Mask Value Processing ↓ Field Reference Resolution ({fieldName} → actual value) ↓ Type Conversion ↓ Field Assignment ↓ Nested Object Processing ↓ Output Masked Object (new instance, original unchanged)

Field Reference Resolution

  • Default Pattern: {fieldName} — regex \{([^}]+)\}
  • Custom Patterns: Configurable via MaskMeFieldAccessUtil.setUserPattern()
  • Supports {}, [], (), <>, [[]]

Thread Safety Architecture

private static final ThreadLocal<Map<Class<? extends MaskMeCondition>, Object>>
        conditionInputs = new ThreadLocal<>();
  • Thread isolation prevents cross-request contamination
  • No synchronization overhead
  • MaskMeInitializer — automatic cleanup in finally blocks
  • MaskMeProcessor — manual clearInputs() required

Performance Characteristics

AspectComplexityNotes
Field DiscoveryO(n)n = number of fields
Condition EvaluationO(c)c = conditions per field, first match wins
Type ConversionO(1)Most types
Overall (flat)O(n × c)Flat objects
Overall (nested)O(n × c × d)d = nesting depth
MemoryO(n)Object duplication

Error Handling

  • Graceful Degradation: Returns null for unknown types
  • Logging: Warns about non-critical failures
  • Fallback: Uses reflection when framework injection fails
  • Propagation: Critical errors bubble up as MaskMeException
