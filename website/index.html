🔒 MaskMe

A modern, annotation-based Java library for dynamically masking sensitive data in objects. Supports classes, records, conditional masking, and any framework.

✓ Annotation-based ✓ Conditional masking ✓ Framework-agnostic ✓ Thread-safe ✓ Java 17+

Key Features

🏷️

Annotation-Based

Simple @MaskMe annotation on any field or record component.

🔀

Conditional Masking

Mask based on runtime conditions — roles, environment, time, or custom logic.

🔌

Framework-Agnostic

Works with Spring, Quarkus, or pure Java. You choose the integration.

🧵

Thread-Safe

ThreadLocal-based input management. Safe for concurrent web requests.

📎

Field Referencing

Dynamic {fieldName} syntax to build mask values from other fields.

🔄

Custom Converters

Override default type conversion with scoped, priority-based converters.

5-Minute Quick Start

1

Add the Dependency

Add MaskMe to your project using Maven or Gradle (see Installation above).

2

Annotate Your Data

public record UserDto(
        @MaskMe(conditions = {AlwaysMaskMeCondition.class}, maskValue = "****")
        String password,

        @MaskMe(conditions = {MaskMeOnInput.class}, maskValue = "{name}@masked.com")
        String email,

        String name // Used in the field reference above
) {}
3

Use in Your Application

@RestController
public class UserController {

    @GetMapping("/user/{id}")
    public UserDto getUser(@PathVariable Long id,
                           @RequestHeader("X-Mask-Level") String maskLevel) {

        UserDto dto = userService.getUserDto(id);
        return MaskMeInitializer.mask(dto, MaskMeOnInput.class, maskLevel);
    }
}
4

Configure Your Framework (Optional)

For production use with dependency injection, see the framework-specific guides:

  • Spring Setup
  • Quarkus Setup

Quick Examples

Basic Masking

// Always mask
@MaskMe(conditions = {AlwaysMaskMeCondition.class}, maskValue = "***")
String sensitiveData;

// Conditional masking
@MaskMe(conditions = {MaskMeOnInput.class}, maskValue = "HIDDEN")
String conditionalData;

Field References

@MaskMe(conditions = {AlwaysMaskMeCondition.class}, maskValue = "{firstName}@company.com")
String email; // Results in "Ahmed@company.com" if firstName is "Ahmed"

Multiple Conditions

@MaskMe(conditions = {RoleBasedCondition.class, EnvironmentCondition.class})
String data; // Masked if ANY condition returns true

Logging Configuration

MaskMe includes zero-overhead logging disabled by default for production performance.

Via System Properties

-Dmaskme.logging.enabled=true -Dmaskme.logging.level=DEBUG

Via Environment Variables

export MASKME_LOGGING_ENABLED=true
export MASKME_LOGGING_LEVEL=DEBUG

Programmatically

MaskMeLogger.enable(Level.FINE);  // DEBUG level
MaskMeLogger.enable(Level.INFO);  // INFO level
MaskMeLogger.disable();            // Disable completely
LevelJava MappingWhat Gets Logged
DEBUGLevel.FINECondition creation, field processing traces
INFOLevel.INFOProcessor initialization, framework setup
WARNLevel.WARNINGFallback conversions, missing fields
ERRORLevel.SEVERECondition creation errors, invalid inputs

Best Practices

🚀 Startup

  • Configure framework provider once at startup
  • Clear global converters to prevent leaks
  • Register custom converters after clearing

🫘 Bean Management

  • Declare conditions as framework beans
  • Use DI for custom conditions
  • Leverage framework config properties

🧹 Memory

  • Use lifecycle hooks to clear converters
  • Clear request-scoped converters in finally blocks
  • Avoid leaks with proper ThreadLocal cleanup

🧪 Testing

  • Use thread-local converters for isolation
  • Clear converters in @BeforeEach/@AfterEach
  • Test with different condition inputs

Troubleshooting

NoSuchBeanDefinitionException (Spring/Quarkus) Declare built-in conditions as beans in your configuration. See the framework-specific guides.
Memory Leaks Use MaskMeInitializer for automatic cleanup (recommended), or always call clearInputs() in finally blocks.
Type Conversion Errors Provide valid mask values for the field type. Check supported types in the converter documentation.
